# Corbits

[English](README.md) | **한국어**

자기 말만 믿지 않는 자율 브라우저 에이전트입니다. 목표를 제출하면 Corbits가 계획을 세우고, 샌드박스 브라우저에서 행동하고,
**결과에 영향을 주는 행동 전에는 반드시 사람의 승인을 받고**, 실제 페이지를 완료 기준과 코드로 대조한 뒤에만 성공을 보고합니다.
설계 규칙은 [CLAUDE.md](CLAUDE.md)를 보세요.

- **주장이 아니라 검증.** 완료 기준이 최종 페이지에서 성립해야만 작업이 `completed`가 됩니다.
  기준이 전혀 없으면 성공이 아니라 `unverified`로 끝납니다.
- **결과에 영향을 주는 행동(전송, 게시, 삭제, 구매)은 승인 필수.** 코드가 강제하며, 사용자에게 보여 준 정확한 요소와 페이지에 묶여 있습니다.
- **샌드박스 브라우저.** Chromium이 잠긴 컨테이너 안에서 돌고, 유일한 출구는 사설 주소를 거부하는 프록시입니다.
- **추적 가능.** 모든 단계, 승인, 검증 결과, 스크린샷이 저장되고 대시보드에 표시됩니다.
- **선택 사항인 Jev**(빠른 판단 모델)가 단순한 클릭 단계를 맡아 Claude 호출과 비용을 줄여 줍니다.

상태: 초기 단계이며, 한 명(또는 소수)이 직접 운영하는 용도로 만들었습니다. 먼저 [알려진 한계](#알려진-한계)를 읽어 보세요.

## 로컬에서 실행하기

### 필요한 것

- **Node.js 22.12 이상**과 **pnpm** (`corepack enable`로 pnpm을 쓸 수 있습니다)
- **Docker** (Postgres와 브라우저 샌드박스가 컨테이너로 돕니다. 처음 빌드할 때 약 3.5 GB 이미지를 받습니다)
- **Claude 로그인**: [Claude Code](https://code.claude.com)를 설치하고 로그인해 두세요(`claude auth login`).
  Corbits는 기본적으로 그 로그인을 쓰므로 API 키가 필요 없습니다. API 키를 쓰려면 `.env`에
  `CORBITS_MODEL_PROVIDER=api`와 `ANTHROPIC_API_KEY`를 설정하세요.

### 시작하기

```bash
git clone https://github.com/jin-codes/corbits-public.git
cd corbits-public
pnpm install
cp .env.example .env
```

`.env`에서 세 값을 채웁니다(각 명령이 값을 출력하니 `=` 뒤에 붙여 넣으세요).

```bash
# CORBITS_API_TOKENS  -> 로그인 토큰, owner:token 형식
node -e "console.log('me:'+require('crypto').randomBytes(32).toString('hex'))"
# CORBITS_SECRETS_KEY -> 저장된 로그인 정보를 암호화합니다. 백업해 두세요
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
# CORBITS_BROWSER_WS_SECRET -> 브라우저 샌드박스를 보호합니다
node -e "console.log(require('crypto').randomBytes(24).toString('hex'))"
```

그다음:

```bash
pnpm docker:up      # Postgres + 샌드박스 브라우저 (처음엔 이미지를 빌드하느라 몇 분 걸립니다)
pnpm start          # API, 대시보드, 워커가 http://127.0.0.1:8787 에서 시작됩니다
```

<http://127.0.0.1:8787/> 을 열고, `CORBITS_API_TOKENS`에서 `me:` **뒤의** 부분으로 로그인하세요.

### 첫 작업 해 보기

대시보드에서 다음을 제출합니다.

- **목표:** `Open https://example.com and tell me, in one sentence, what the page says this domain is for.`
- **완료 기준:** 페이지 텍스트에 `documentation examples`가 포함됨

페이지를 열고 나서 `Completed and verified`(완료 및 검증됨)가 표시되어야 합니다. 기준을 페이지에 없는 내용으로 바꾸면 에이전트가
끝났다고 말해도 같은 실행이 `Failed`로 끝납니다. 이것이 핵심입니다.

API로도 똑같이 할 수 있습니다.

```bash
TOKEN=...   # CORBITS_API_TOKENS에서 "me:" 뒤의 부분
curl -s -X POST http://127.0.0.1:8787/tasks \
  -H "authorization: Bearer $TOKEN" -H 'content-type: application/json' \
  -d '{"goal":"Open https://example.com and tell me what this domain is for.",
       "completionCriteria":[{"kind":"text_present","value":"documentation examples"}]}'
```

팁: 목표에 따옴표로 묶은 문구를 넣으면(`... find "Pro plan"`) 완료 기준을 따로 주지 않아도, Corbits가 그 문구가
최종 페이지에 있어야 한다고 요구합니다.

### 멈추고 정리하기

```bash
pnpm docker:down            # 컨테이너를 멈춥니다 (데이터는 Postgres 볼륨에 남습니다)
docker compose down -v      # 데이터베이스 볼륨까지 삭제합니다: 모든 작업과 저장된 로그인이 사라집니다
```

### 문제가 생기면

| 증상 | 가능한 원인 |
|---|---|
| `pnpm docker:up`에서 `set CORBITS_BROWSER_WS_SECRET in .env` | `.env`의 시크릿이 비어 있습니다. |
| 포트가 이미 사용 중(5432, 9222, 8787) | 다른 Postgres나 Corbits가 돌고 있습니다. 멈추거나, `.env`의 `PORT`와 `CORBITS_BROWSER_PORT`를 바꾸세요(Postgres 포트는 `docker-compose.yml`에 있습니다). |
| 작업이 모델 오류로 바로 실패 | Claude Code에 로그인되어 있지 않습니다(`claude auth login`). 또는 위에서 말한 대로 API 키를 쓰세요. |
| 시작할 때 `Invalid configuration` | `.env`에 값이 빠졌거나 토큰이 32자보다 짧습니다. 메시지에 어떤 항목인지 나옵니다. |
| 페이지가 맞아 보이는데 작업이 `Failed`로 끝남 | 완료 기준은 화면이 아니라 페이지의 접근성 트리와 대조됩니다. 둘이 다를 수 있습니다(예: `<title>`에만 있는 제목). 작업을 열어 검증기가 본 내용을 확인하세요. |

`pnpm test`는 결정적 테스트 모음을 실행합니다(Postgres 컨테이너가 필요합니다). `pnpm test:live`는 실제 Claude API를 호출하는
테스트로, 몇 센트가 듭니다. `npx playwright install chromium`은 샌드박스 없이 돌릴 때(`CORBITS_BROWSER_WS_SECRET` 없음)만
필요하며, 이는 개발 전용입니다.

## 서버에서 실행하기

`docker-compose.prod.yml`은 전체 스택(앱, Postgres, 샌드박스 브라우저, 게이트웨이)을 한 대의 머신에서 돌리므로, 노트북이 꺼져 있어도
Corbits가 계속 동작합니다. arm64와 x86 모두에서 빌드됩니다. Oracle Cloud Always Free와 Tailscale 접속에 대한 단계별 안내는
[docs/deploy-oracle.md](docs/deploy-oracle.md)에 있습니다. 대화형 로그인이 없는 서버에서는 모델 백엔드가
`CLAUDE_CODE_OAUTH_TOKEN`(`claude setup-token`으로 발급, 구독 계정, 개인 사용)을 사용합니다.

## 모델 접근: API 키가 아니라 내 Claude 로그인

기본적으로 Corbits는 로컬에 설치되어 로그인된 Claude Code(`claude -p`)에 매번 판단을 맡깁니다. 그래서 사용량은 Claude 구독에서 차감되고
API 키가 필요 없습니다. Corbits는 자체 루프, 정책 엔진, 승인, 한도를 그대로 유지하며, Claude Code는 텍스트를 넣으면 JSON이 나오는
모델로만 쓰입니다. 내장 도구는 모두 꺼져 있고, 모든 사용자 설정(CLAUDE.md, 훅, MCP 서버, 메모리)도 꺼져 있으며, 아무것도 저장하지 않고,
빈 디렉터리에서 실행되며, 최소한의 환경만 전달됩니다(`ANTHROPIC_API_KEY`도, Corbits의 시크릿도 없음). 어떤 백엔드가 각 단계를
결정했는지는 기록에 남습니다.

- 표시되는 비용은 Claude Code가 API 가격으로 추정한 값입니다. 지출 한도는 이 값을 기준으로 적용되며, 실제 청구액이 아닙니다.
  구독 사용량 한도는 그대로 적용되고, 한도에 걸리면 작업이 분명한 메시지와 함께 실패합니다.
- 단계마다 CLI 프로세스를 시작하므로 API를 쓸 때보다 단계당 1~2초가 더 걸립니다.
- 구독 로그인은 본인 사용을 위한 것입니다. 나중에 다른 사람에게 Corbits를 제공하게 되면 API 키를 쓰는
  `CORBITS_MODEL_PROVIDER=api`로 바꾸세요. Anthropic은 제3자 제품이 claude.ai 로그인을 제공하는 것을 허용하지 않습니다.

## 언어

대시보드, 읽기 쉬운 작업 기록, 결과 설명, 이메일은 기본적으로 한국어로 작성됩니다. 영어로 보려면 `CORBITS_LOCALE=en`을 설정하세요.
이 모든 문구는 하나의 카탈로그(`src/i18n/messages.ts`)에 있고, TypeScript가 모든 메시지가 두 언어에 모두 있도록 강제하며,
테스트가 자리표시자, 번역 누락, 대시보드 스크립트의 영어 하드코딩 여부를 확인합니다. AI는 계획과 최종 보고를 목표를 쓴 언어로 작성하도록
지시받으므로, 한국어 목표에는 한국어 계획과 보고가 나옵니다. API 오류 코드와 서버 로그는 영어로 유지됩니다.

## 브라우저 샌드박스

`CORBITS_BROWSER_WS_SECRET`(무작위 24자 이상, `docker compose`가 `.env`에서 보는 값과 동일)을 설정하면,
작업이 내 컴퓨터가 아니라 컨테이너 안의 Chromium에서 실행됩니다.

- **browser** 컨테이너: 비루트, 읽기 전용 루트 파일시스템, `SYS_CHROOT`(Chromium 자체 샌드박스에 필요)를 제외한 모든 capability 제거,
  seccomp 프로필, no-new-privileges, 메모리와 프로세스 제한, 호스트 마운트 없음, 그리고 **인터넷이나 내 컴퓨터로 가는 경로가 없음**.
- **gateway** 컨테이너: 브라우저의 유일한 출구입니다. 이 컨테이너의 송신 프록시는 사설 네트워크(내 컴퓨터, 다른 컨테이너, 클라우드
  메타데이터)를 거부하고, 각 연결을 검증한 주소에 고정합니다. 또한 `127.0.0.1:9222`를 브라우저의 제어 소켓으로 중계하며, 이 소켓은
  비밀 경로 뒤에 있습니다.

시크릿이 없으면 앱은 내 컴퓨터의 Chromium으로 대체되고 시작할 때 그 사실을 알립니다. 개발할 때만 쓰세요. `pnpm test:docker`는 샌드박스의
별도 사본을 띄워 이 속성들을 실제 컨테이너로 확인합니다(Docker와 인터넷이 필요합니다).

샌드박스의 한계: 모든 작업이 하나의 Chromium 프로세스를 공유하고(각각 별도의 브라우저 컨텍스트), 프록시는 URL 경로가 아니라 호스트와 주소로
거르며, 처음 `pnpm docker:up`을 하면 3.5 GB 이미지를 받습니다.

## 실패한 작업 이어서 하기

실패했거나 취소된 작업의 페이지에는 **이어서 하기** 섹션이 있습니다. 이전 작업에 연결된 *새* 작업을 시작합니다(이전 작업과 그 기록은 절대
바뀌지 않습니다). 같은 목표와 완료 기준, 이미 한 일과 멈춘 이유의 요약, 마지막으로 있던 페이지, 선택 사항인 메모("이번엔 저장된 비밀번호를
써 줘"), 새 예산(서버 최대치를 넘지 않음)이 담깁니다. 이전 브라우저의 로그인은 이어지지 않습니다. `POST /tasks/:id/continue`로 API에서도
같은 일을 할 수 있습니다. 이전 시도가 안전하게 반복할 수 없는 행동의 도중에 멈췄다면, 요약에 그 사실이 적히고 에이전트는 행동하기 전에
페이지를 확인하라는 지시를 받습니다.

## 저장된 로그인 정보(로그인 금고)

어떤 작업은 비밀번호가 필요합니다. **로그인 정보** 메뉴(또는 `POST /secrets`)에서 이름과 사용할 사이트와 함께 한 번 저장해 두세요.
그러면 목표에 비밀번호를 붙여 넣지 않고도 작업이 로그인할 수 있습니다.

- AI는 **이름**(과 어느 사이트용인지)만 알고, 값은 절대 알지 못합니다. 브라우저가 별도의 도구로 직접 입력하는데, 이 도구는
  **정확히 그 사이트의 비밀번호 입력란에서만** 동작하고 작업 소유자 본인의 로그인 정보에만 쓸 수 있습니다.
- **사용할 때마다 승인이 필요합니다.** 승인 카드에는 입력란, 페이지, 사이트, 로그인 정보 이름과 스크린샷이 표시되고 승인은 그것들에 묶입니다.
  페이지가 바뀌면 다시 묻습니다. 잘못된 사이트나 비밀번호 입력란이 아닌 곳에서의 사용은 묻지도 않고 바로 거부됩니다.
- 값은 AES-256-GCM으로 암호화되어 저장되고(키는 `CORBITS_SECRETS_KEY`, 소유자·이름·사이트에 묶임) 쓰기 전용입니다. 어떤 API도 값을
  돌려주지 않으며, 기록, 승인, 로그에서 지워집니다. 입력된 비밀번호는 스크린샷에서 점으로 보입니다.
- 사용자 이름과 이메일은 비밀이 아니므로 목표에 쓰세요.
- **미리 저장하지 않아도 됩니다.** 맞는 저장된 로그인 정보가 없으면, 에이전트는 승인을 요청하면서 비밀번호도 함께 요청합니다. 승인
  카드에 비밀번호 입력란이 나타납니다. 입력한 값은 브라우저에 한 번 전달된 뒤 삭제됩니다(승인된 행동이 실행될 때까지만 암호화되어
  보관되고, 사용되지 않으면 30분 뒤 폐기됩니다). "다음에도 쓰도록 저장"을 체크하면 해당 사이트용으로 이름을 붙여 보관합니다. AI, 기록,
  스크린샷에는 절대 포함되지 않습니다.
- `CORBITS_SECRETS_KEY`를 설정하면 사용할 수 있습니다(`.env.example` 참고). **키를 백업하세요.** 없으면 저장된 로그인 정보를 복구할 수
  없습니다. 2단계 인증 코드나 CAPTCHA는 다루지 않습니다.

## 승인된 행동은 승인된 그대로 실행됩니다

행동을 승인하면, 시스템은 AI에게 다시 묻고 같은 제안이 나오길 기대하는 대신 정확히 그 행동을 곧바로 실행합니다. 그 사이에 페이지나
대상이 바뀌었다면 승인은 폐기되고 다시 묻습니다. 승인은 반복해서 재시도되지 않습니다.

## 증거와 파일

작업이 실행되는 동안 Corbits는 나중에 확인할 수 있는 증거를 남깁니다. 브라우저 행동마다 스크린샷, 승인을 요청한 순간의 페이지 스크린샷
(승인 카드에 표시되므로 무엇을 승인하는지 볼 수 있음), 그리고 검증할 때마다 스크린샷과 검증기가 본 전체 페이지 텍스트입니다. 작업이
중간에 멈추면 최종 상태의 스크린샷이 추가됩니다. 연속해서 동일한 스크린샷은 한 번만 저장됩니다.

- 파일은 `ArtifactStore` 인터페이스 뒤의 Postgres(`artifacts` 테이블)에 저장됩니다. 파일당(2 MB), 작업당(80개, 40 MB) 한도가
  있으며, 용량이 가득 차면 기록에 한 번 알립니다.
- 스크린샷에는 민감한 내용이 보일 수 있으므로 `CORBITS_ARTIFACT_RETENTION_DAYS`(기본 30일) 뒤에 만료되고, 소유자는 언제든
  삭제할 수 있습니다(`DELETE /artifacts/:id`). 수집한 페이지 텍스트에서는 비밀이 지워지지만 스크린샷에서는 지울 수 없습니다.
- 증거 수집은 최선을 다하되 시간 제한이 있습니다. 수집에 실패하면 기록에 남기지만 작업의 결과는 절대 바꾸지 않습니다.
- `GET /tasks/:id/artifacts`로 목록을, `GET /artifacts/:id`로 바이트를 가져옵니다(소유자 전용, 엄격한 CSP와 nosniff 적용,
  텍스트는 다운로드로 제공).

## 대시보드

http://127.0.0.1:8787/ 을 열고 API 토큰 중 하나로 로그인하세요(그 브라우저 탭에서만 유지됩니다). 여기서 완료 기준과 한도를 정해
작업을 제출하고, 진행 상황을 실시간으로 보고, 멈춘 행동을 승인하거나 거부하고(정확한 요소와 폼 대상이 표시됨), 취소하고, 검증에 쓰인
증거가 포함된 쉬운 말의 기록을 읽을 수 있습니다. 끝난 작업의 "에이전트 보고"는 AI가 쓴 것이며, 코드가 확인하는 것은 완료 기준뿐입니다.

## API

`/healthz`를 제외한 모든 경로에는 `Authorization: Bearer <token>`이 필요합니다. 다른 소유자의 작업은 존재하지 않는 것처럼 보입니다(404).

| 메서드 | 경로 | 용도 |
|---|---|---|
| POST | `/tasks` | `{ goal, completionCriteria?, limits? }` 제출 |
| GET | `/tasks` | 내 작업 목록, 최신순(`limit`, `before`) |
| GET | `/tasks/:id` | 상태, 대기 중인 승인, 마지막 상태 변경의 이유 |
| GET | `/tasks/:id/events` | 원본 실행 기록(`after`, `limit`) |
| GET | `/tasks/:id/timeline` | 읽기 쉬운 기록, 비용, 결과(대시보드에 표시되는 내용) |
| GET | `/tasks/:id/artifacts` | 작업의 스크린샷과 수집한 페이지 텍스트 |
| GET | `/artifacts/:id` | 파일 하나(소유자 전용) |
| DELETE | `/artifacts/:id` | 파일 하나 삭제 |
| GET/POST | `/schedules` | 내 예약 목록 / 새로 만들기 `{ name, goal, schedule, timezone, completionCriteria?, limits?, logins? }` |
| PATCH/DELETE | `/schedules/:id` | 일시정지·재개(`{ enabled }`), 이름 변경 / 삭제 |
| POST | `/schedules/:id/run` | 지금 실행 |
| GET | `/schedules/:id/runs` | 시각이 될 때마다 일어난 일(건너뜀과 그 이유 포함) |
| GET | `/me` | 나는 누구인지, 역할, 한도와 오늘 사용량, 내 API 키가 저장되어 있는지 |
| PUT/DELETE | `/me/api-key` | 내 Anthropic API 키 저장(Anthropic이 동작을 확인한 뒤) 또는 삭제 |
| GET/POST | `/admin/users` | 관리자: 사용자 목록 / 추가(토큰은 한 번만 반환) |
| PATCH | `/admin/users/:owner` | 관리자: 비활성화·활성화, 이메일·역할·한도 변경 |
| POST | `/admin/users/:owner/token` | 관리자: 새 토큰 발급(이전 토큰은 즉시 무효) |
| POST | `/auth/code` | API 토큰 전용: 일회용 대시보드 로그인 코드(60초, 1회 사용) |
| POST | `/auth/redeem` | `{ code }`(토큰 불필요): 코드를 12시간짜리 세션 토큰으로 교환 |
| POST | `/tasks/:id/cancel` | 취소 |
| GET | `/tasks/:id/live` | 작업 브라우저의 JPEG(실행 중, 승인 대기, 또는 사람이 제어하는 중) |
| POST | `/tasks/:id/control/take` | 에이전트를 멈추고 브라우저를 직접 제어(실행 중인 작업만) |
| POST | `/tasks/:id/control/input` | 제어하는 동안: `{type:"click",x,y}`, `{type:"text",text}`, `{type:"key",key}`, `{type:"scroll",x,y,dx,dy}` |
| POST | `/tasks/:id/control/release` | 브라우저를 에이전트에게 돌려줌. 에이전트에게 전할 `{ "note" }`를 선택적으로 포함 |
| GET | `/approvals` | 내 결정을 기다리는 행동 |
| POST | `/approvals/:id/decision` | `{ "decision": "approved" \| "rejected" }` |

완료 기준은 모델이 아니라 코드가 최종 페이지와 대조해 확인합니다.
`{"kind":"url_contains","value":"/done"}` 또는 `{"kind":"text_present","value":"Order confirmed"}`.
결과가 답변인 작업에는 `{"kind":"answer_grounded"}`를 쓸 수 있습니다. 에이전트의 최종 요약에 있는 모든 숫자(두 자리 이상이거나 소수점이
있는 것)와 큰따옴표로 묶인 모든 텍스트를 최종 페이지에서 찾아봅니다. 말한 값이 페이지에 있는지를 확인할 뿐, 답이 옳은지를 확인하는 것은
아닙니다. 완료 기준이 전혀 없는 작업도 실행은 되지만 `unverified`로 끝납니다.
요청하는 `limits`(`maxToolCalls`, `maxRuntimeMinutes`, `maxSpendUsd`, `maxSteps`, `maxRecoveryAttempts`)는 서버 최대치보다 낮게만 정할 수
있습니다.

```bash
curl -s -X POST http://127.0.0.1:8787/tasks \
  -H "authorization: Bearer $TOKEN" -H "content-type: application/json" \
  -d '{"goal":"Open https://example.com and confirm it says Example Domain",
       "completionCriteria":[{"kind":"text_present","value":"Example Domain"}]}'
```

## 예약 작업

예약은 정해진 시각에 작업을 스스로 시작하므로, 자리를 비운 동안에도 일이 진행됩니다. **예약 작업**(예약)을 열어 이름을 붙이고, 할 일을 적고,
완료 기준을 정하고, 시각을 고르세요. 매일 정해진 시각, 고른 요일의 정해진 시각, 또는 N분마다(최소 15분) 중에서 고를 수 있습니다. 시각은
예약의 시간대(기본값은 브라우저의 시간대) 기준 벽시계 시각이므로, 서머타임이 바뀌어도 08:30은 08:30으로 유지됩니다.

- **매 실행은 평범한 작업입니다.** 고유한 기록, 증거, 한도, 승인, 알림 이메일이 있고 "예약에 의해 시작됨 ..."이라고 표시됩니다.
  지출 한도는 예약 자체에 지정하세요. 모든 실행에 적용됩니다. 예약은 체크한 저장된 로그인으로 로그인된 상태로 시작할 수도 있습니다.
- **쌓이지 않습니다.** 이전 실행이 아직 진행 중이면 새 시각은 건너뛰고 이유를 기록합니다. 승인이나 도움을 12시간 넘게 기다린 실행은
  취소되어 이후의 모든 실행을 막지 못하게 합니다.
- **놓친 시각을 보충하지 않습니다.** 서버가 꺼져 있던 시간이 정해진 시각을 1시간 넘게 지났다면 그 실행은 건너뛰고 기록합니다(몇 분
  꺼져 있었다면 돌아왔을 때 실행됩니다). 일시정지한 예약을 재개하면 지금부터 앞을 봅니다.
- **계속 실패하면 스스로 멈춥니다.** 연속 5번 실패하면 예약이 일시정지되고(이유가 표시됨), 동작하지 않는 일에 비용을 쓰지 않습니다. 고친
  뒤 다시 켜세요.
- 사용자별 한도는 평소처럼 적용됩니다(동시 작업 수, 일일 지출, 시간당 작업 수, 쓸 수 있는 모델). 한도를 넘었거나, 비활성화된 사용자이거나,
  API 키가 없는 사용자의 실행은 아무것도 시작하지 않고 **최근 실행**에 이유를 보여 줍니다.
- **지금 실행**은 예약을 바꾸지 않고 즉시 하나를 시작합니다. 사용자당 최대 20개의 예약을 만들 수 있습니다.
- 예약은 서버 프로세스가 30초마다 확인하므로 Corbits가 실행 중일 때만 동작합니다. 잠자는 노트북에서는 실행이 늦거나 건너뛰어집니다(위
  참고). 서버 배포에서는 그냥 동작합니다. `CORBITS_SCHEDULER=0`으로 끌 수 있습니다.

## 저장된 브라우저 로그인

사이트에 직접 한 번 로그인해 두면, 이후 작업은 비밀번호를 입력하지 않고도 이미 로그인된 상태로 시작할 수 있습니다.

1. 작업을 시작하고(또는 실행 중인 작업을 열고) **직접 개입하기**를 누른 뒤, 라이브 브라우저에서 로그인합니다. CAPTCHA나 2단계 코드도
   여기서 처리하세요.
2. **이 로그인 유지하기**를 열고 이름(예: `mail`)을 붙인 뒤 **이 로그인 저장**을 누릅니다.
3. 새 작업을 시작할 때 **로그인된 상태로 시작할 사이트**에서 그 로그인을 체크합니다. 작업의 브라우저가 그 로그인으로 시작하고
   에이전트는 거기에 로그인되어 있다는 것을 알게 됩니다. 체크하지 않으면 아무것도 불러오지 않습니다.

- 열려 있는 페이지의 사이트(쿠키와 로컬 스토리지)만 저장되며, 브라우저가 우연히 가지고 있는 다른 사이트는 절대 저장되지 않습니다.
  로그인은 `https` 페이지에서만(또는 개발용으로 이 컴퓨터에서) 저장할 수 있습니다.
- `CORBITS_SECRETS_KEY`로 암호화되어 저장되고, 나와 이름과 사이트에 묶이며, 쓰기 전용입니다. 목록에는 이름, 사이트, 날짜만 보이고 세션은
  보이지 않습니다. 에이전트는 사이트와 이름만 압니다. 기록에는 로그인이 저장되거나 사용되었다는 사실(이름, 사이트, 쿠키 개수)만 남고 값은
  절대 남지 않으며, 값이 어딘가에 나타났다면 로그와 증거에서 지워집니다.
- 이것은 사이트가 내 브라우저에 준 것의 사본일 뿐이므로, 사이트가 정한 시점에(또는 다른 곳에서 로그아웃하면) 만료됩니다. 그래도 작업이
  로그인 페이지를 만나면 에이전트가 도움을 요청합니다. 다시 로그인하고 다시 저장하세요. **저장된 로그인** 페이지에서 언제든 삭제할 수
  있습니다. 작업을 이어서 하면 같은 로그인이 유지됩니다.
- 로그인된 상태에서는 그 사이트에서 내 이름으로 행동할 수 있으므로, 필요한 작업에서만 로그인을 체크하세요. 결과에 영향을 주는 행동은
  평소처럼 승인이 필요합니다. 샌드박스 브라우저나 로컬 Chromium이 필요하며, "내 Chrome" 모드에는 불러오지 않습니다(실제 쿠키가 바뀌게
  되므로).

## 에이전트 평가하기

`pnpm eval`은 로컬 테스트 사이트를 대상으로 실제 모델과 실제 브라우저로 작은 작업 열 개를 돌리고, Corbits가 얼마나 자주 맞게 처리했는지
보고합니다. 판단은 에이전트나 검증기가 한 말이 아니라 사이트 자체의 기록(어떤 페이지를 방문했는지, 무엇을 구독했는지, 심어 둔 지시를
따랐는지)으로 하므로, 진짜 성공과 거짓 완료를 구분할 수 있습니다.

```bash
pnpm eval --list                                  # 케이스 목록
pnpm eval                                         # 전부 한 번씩 (약 10분)
pnpm eval --cases read-price,impossible --repeat 3
pnpm eval --recovery 0 --label no-recovery        # 설정 비교: 실행에 라벨을 붙이고 파일을 비교
```

- 케이스는 읽기, 이동, 폼, 검색, 기록 조회, 소유자가 승인하는 행동, 같은 행동을 소유자가 거부하는 경우(일어나면 안 됨), 에이전트를
  가로채려는 페이지, 할 수 없는 작업(성공했다고 주장하면 안 됨), 사람만 할 수 있는 단계(도움을 요청해야 함)를 다룹니다.
- 보고서에는 성공률, 거짓 완료율, 복구 성공률, 정답 작업당 비용, 지연 시간, 도구·모델 호출 수, 승인, 도움 요청, 안전 관련 집계가
  나옵니다. 출력되고, 마크다운과 JSON으로 `eval-results/`(git 제외)에 저장됩니다.
- 각 작업은 추정 사용량 약 $0.50로 제한됩니다. 표시되는 비용은 구독이 청구하는 금액이 아니라 Claude Code가 API 가격으로 추정한 값이며,
  구독 한도는 그대로 적용됩니다.
- 실행하는 동안 Mac이 잠들지 않게 하세요(`caffeinate -i pnpm eval`). 중간에 잠들면 시간과 한도가 의미 없어집니다. 로컬 Postgres
  (`pnpm db:up`)와 Chromium이 필요합니다.

## 여러 사람이 쓰기

`CORBITS_API_TOKENS`의 토큰은 **관리자**입니다. 관리자는 대시보드에서 **사용자**를 열어 사람을 추가하고(이름, 선택적으로 알림용 이메일과
다른 한도), 그 사람의 토큰을 한 번 받습니다. 비공개로 전달하세요. 상대는 로그인 페이지에 붙여 넣습니다.

- 모든 사람은 자신의 작업, 기록, 증거, 승인, 저장된 로그인만 봅니다. 관리자도 다른 사람의 작업은 보지 못합니다. 알림 이메일은 각자의
  주소로 갑니다.
- 관리자가 아닌 사용자에게는 한도가 있어서 한 사람이 모두의 몫을 쓰지 못합니다. 동시 작업 수(기본 2), 하루 추정 모델 지출(기본 $2,
  UTC 자정에 초기화), 시간당 작업 수(기본 30)입니다. 기본값은 `.env`(`CORBITS_USER_*`)에서, 또는 사용자 페이지에서 사람별로 바꿉니다.
  작업 목록에서 사용량을 볼 수 있고, 한도에 걸리면 분명한 메시지가 나옵니다.
- 관리자는 사용자를 비활성화(열려 있는 대시보드 세션 포함해 즉시 접근 차단)하거나 다시 활성화하거나 새 토큰을 발급(이전 토큰은 즉시
  무효)할 수 있습니다. 토큰은 해시만 저장하므로, 잃어버린 토큰은 조회할 수 없고 교체만 가능합니다. 관리자는 자기 자신을 비활성화하거나
  강등할 수 없습니다.
- **어느 Claude 계정으로 작업이 실행되는가(자기 키 가져오기).** 기본 백엔드는 개인 Claude 로그인(`claude -p`)이며, 본인 사용을 위한
  것이라 남에게 빌려 줄 수 없습니다. 그래서 관리자의 작업은 이것으로 실행되지만, 그 외의 사람은 **자기 Anthropic API 키**를 추가해야
  합니다(**내 API 키** 페이지). 키는 Anthropic에서 확인되고, 암호화되어 저장되며, 마지막 네 글자로만 표시되고, 기록·로그·증거에는 절대
  기록되지 않으며, 그 사람의 작업에만 쓰이므로 사용량은 본인의 Anthropic 계정으로 청구됩니다. 키가 없으면 로그인해서 둘러볼 수는 있지만
  작업을 시작할 수 없고 이유가 안내됩니다. 키가 있는 사람은 일일 지출 한도 대상이 아닙니다(본인의 돈이므로). 서버와 브라우저는 공유하므로
  동시 작업 수와 시간당 한도는 계속 적용됩니다. 서버를 API 키로 운영한다면(`CORBITS_MODEL_PROVIDER=api`), 자기 키가 없는 사람은 그 키를
  일일 한도 안에서 사용합니다. 키를 암호화하려면 저장된 로그인용 키(`CORBITS_SECRETS_KEY`)가 필요합니다. 서버를 장악한 사람은 원칙적으로
  저장된 키를 쓸 수 있으므로, 이 용도로만 지출 한도를 건 키를 따로 만들라고 안내하세요.
- **서버에 접속하기.** 토큰이 요청에 실려 가므로 HTTPS나 사설 네트워크를 쓰세요. Tailscale로 접근을 주는 것(머신을 공유하거나 내
  tailnet에 초대)이 가장 간단하고 안전한 방법입니다. 평문 HTTP 포트를 인터넷에 노출하지 마세요. 가입 페이지는 없고 관리자만 사람을 추가할
  수 있습니다.
- 모두가 같은 브라우저 샌드박스와 서버 자원을 씁니다(작업마다 격리된 브라우저 컨텍스트를 받음). 소수의 사람에게는 충분하지만, 더 많이
  쓰려면 작업별 컨테이너가 필요합니다(로드맵 참고).

## 토큰 아끼기: 기록 줄이기와 Jev

- **프롬프트에서 오래된 페이지 스냅샷을 줄입니다**(기본 켜짐). 페이지 스냅샷은 수만 자가 될 수 있고, 예전에는 매 단계마다 이전 것을 전부
  다시 보냈습니다. 이제 최신 것만 전체를 보내고, 오래된 페이지는 처음 800자만 남깁니다. 저장된 기록은 그대로입니다. 끄려면
  `CORBITS_FULL_HISTORY=1`을 설정하세요(비교용).
- **Jev(`TYPESAFE_API_KEY`가 설정되어 있으면 항상 켜짐).** [Jev](https://docs.typesafe.ai/introduction)는 판단 모델입니다. 닫힌 선택지
  중 하나를 고르고 얼마나 확신하는지 말하지만, 글을 쓰지는 못합니다. "다음에 어떤 링크를 누를까" 같은 단순한 단계를 맡고, 나머지(계획,
  입력, 마무리, 불분명한 모든 것)는 메인 모델이 맡습니다. 작업이 실행되는 모든 모델에 적용되며(사람들의 자기 키 포함), 비용은 `.env`의
  TypeSafe 키로 청구됩니다. 키가 설정되어 있으면 켜지고, 메인 모델만 쓰려면 키를 지우세요.
  - Jev는 클릭만 제안합니다. 다른 모든 행동과 같은 정책 엔진, 승인, 한도를 거치므로 Jev가 무엇이 허용되는지 결정하는 일은 없고, 승인이나
    권한에는 절대 쓰이지 않습니다.
  - 대시보드의 새 작업 양식에서 작업별로 Jev 모드를 고를 수 있습니다(서버 기본값, Jev 우선, Jev 단독, Jev + 요약). 선택은 작업과 함께
    저장되고, 실패한 작업을 이어서 할 때도 유지됩니다. Jev 키가 없으면 아무 영향이 없습니다.
  - **Jev 단독**(작업별, 대시보드 또는 `jevMode: "only"`): Claude 호출이 전혀 없습니다(계획도, 단계도, 요약도 없음). Jev는 확신도와
    상관없이 가장 유력한 답을 따르고(임계값 없음, 위험한 컨트롤은 여전히 제공되지 않고 모든 행동은 여전히 정책 엔진과 승인을 거침), Jev가
    계속할 수 없으면(맞는 것이 없거나, 목표에 없는 값을 입력해야 할 때) 작업이 멈춥니다. 작업에는 요청의 `completionCriteria`나 목표 안의
    따옴표 문구로 완료 기준이 있어야 하며(둘 다 없으면 API가 400으로 답함), 목표에는 시작 주소가 있어야 합니다. 검증은 결정적인 코드가 그대로
    합니다. 아직 측정하지 않았습니다. **Jev + 요약**(`jevMode: "summary"`)은 같은 방식에, 도구 없는 Claude 호출 한 번(설정되어 있으면
    `CORBITS_SUMMARY_MODEL`, 아니면 메인 모델)이 최종 요약만 쓰는 모드로, 조사 작업에 적합합니다. 대시보드는 서버 기본값, Jev 우선, Jev
    단독, Jev + 요약의 네 가지를 제공합니다(API는 여전히 `assist`도 받습니다).
  - 기본 모드는 `first`입니다(2026-10-11부터). Jev가 브라우저 단계를 결정하고 확신도 0.6 이상일 때 행동합니다(0.6 아래로는 설정할 수
    없음). 메인 모델은 계획, 마무리, 텍스트 작성, 위험하거나 불분명한 단계를 맡습니다. 이 목록의 설명처럼 확신도 0.75 이상(설정
    가능)에서 행동하게 하려면 `CORBITS_JEV_MODE=assist`로 설정하세요. 그 아래이거나, "none"이거나, Jev 오류나 시간 초과이거나, 연속 클릭
    세 번 뒤이거나, 거부·반려·검증 실패 뒤에는 메인 모델이 결정합니다. Jev가 중단되어도 작업은 멈추지 않습니다.
  - 페이지 텍스트는 신뢰할 수 없으므로 Jev는 짧은 한 줄짜리 요소 이름과 링크가 가는 곳만 보고(원본 페이지 텍스트는 절대 보지 않음),
    행동처럼 들리는 이름의 요소(삭제, 구매, 구독, 로그인 등)는 아예 제공되지 않으며, Jev가 첫 번째 선택지에 치우치는 경향이 있어
    선택지는 섞어서 보여 줍니다.
  - Jev 단계는 기록에 표시되고(`via: jev`) 따로 집계됩니다. Jev의 가격은 문서에 공개되어 있지 않아서, 표시되는 비용에는 포함되지
    않습니다.
  - 측정한 뒤에 켰습니다. 쉬운 케이스와 어려운 케이스에서 전체 단계의 6~8%를 맡았고, 잘못 클릭한 적이 없으며, 메인 모델의 토큰을 전체
    약 11%(Jev가 행동한 작업에서는 21~30%) 줄였습니다. `docs/eval-jev-comparison.md`를 보세요. `pnpm eval --jev --label jev`와
    `pnpm eval --label baseline`을 비교해 다시 확인할 수 있습니다(`--jev`는 평가 도구에서 강제로 켭니다).

## 메뉴 막대 앱(macOS)

작은 메뉴 막대 항목이 실행 중인 작업 수와 승인을 기다리는 작업 수를 보여 주고(새 승인이 오면 macOS 알림이 뜸), 이미 로그인된 상태로
대시보드를 열어 클릭한 작업으로 바로 이동합니다. "직접 개입하기"가 한 번의 클릭 거리에 있습니다.

```bash
pnpm menubar install     # 빌드(Xcode 명령줄 도구 필요)하고, 시작하고, 로그인할 때마다 시작되게 합니다
pnpm menubar uninstall   # 멈추고 설치한 것을 제거합니다
pnpm menubar run         # 먼저 터미널에서 시험해 보세요
```

- 이 프로젝트의 `.env`에서 API 토큰을 읽어 메모리에만 보관합니다.
- 토큰을 URL에 넣지 않습니다. 서버에 일회용 코드(1분간 유효, 1회 사용)를 요청하고, 대시보드가 그것을 12시간 동안 유효하며 서버가 재시작되면
  잊혀지는 세션 토큰으로 교환합니다. 세션으로는 대시보드를 열 수 있지만 코드를 더 만들 수는 없습니다.
- 메뉴에서 종료하면 다음 로그인 때까지 종료된 상태로 유지됩니다. 기본적으로 `127.0.0.1:8787`과 통신합니다(`.env`의 `PORT`.
  다른 곳, 예를 들어 Tailscale 주소를 가리키려면 `CORBITS_MENUBAR_URL`).

## 내 Chrome 사용하기(로컬 전용, 선택)

기본적으로 에이전트는 샌드박스 컨테이너에서 일합니다. 이미 로그인해 둔 사이트를 쓰게 하려면, 대신 이 컴퓨터의 Chrome을 제어하게 할 수
있습니다. 보호 수준을 편의와 맞바꾸는 것이므로 기본은 꺼져 있고, 안전하게 설정되어 있지 않으면 시작을 거부합니다.

```bash
pnpm chrome        # 원격 디버깅이 127.0.0.1:9223 에 켜진 별도의 Chrome 프로필(~/.corbits-chrome)을 엽니다
```

에이전트가 쓰길 원하는 사이트에 그 창에서 로그인하세요(한 번만 하면 프로필이 기억합니다). 그다음 `.env`에 다음을 넣습니다.

```
CORBITS_BROWSER_CDP_URL=http://127.0.0.1:9223
CORBITS_ALLOWED_ORIGINS=https://mail.example.com,https://app.example.com
```

- 평소 쓰는 프로필이 아니라 **전용 프로필**이어야 합니다. Chrome 136 이상은 기본 프로필에서 원격 디버깅을 일부러 거부합니다. 쿠키를
  훔치는 데 쓰였기 때문입니다([Chrome 공지](https://developer.chrome.com/blog/remote-debugging-port)).
- 에이전트는 **자기 탭**을 열고 그 탭만 건드립니다. 다른 탭을 닫거나 바꾸지 않으며, 작업을 멈추면 그 탭만 닫습니다. 그 Chrome 창에서
  지켜볼 수 있습니다.
- **필수**: `CORBITS_ALLOWED_ORIGINS`. 에이전트는 목록에 적은 사이트로만 이동할 수 있어서, 그 프로필이 로그인된 다른 사이트로 헤매 들어갈
  수 없습니다. 이 설정이 없으면 Corbits는 시작을 거부하며, 주소는 이 컴퓨터여야 합니다.
- **의도적으로 모든 사이트 허용**: 목록 대신 `CORBITS_ALLOW_ANY_ORIGIN=true`를 설정할 수 있습니다. 그러면 에이전트가 어떤 공개 사이트든
  방문할 수 있어서, 한 페이지에 주입된 텍스트가 에이전트를 그 프로필이 로그인된 다른 사이트로 유도할 수 있습니다. 사설 주소는 계속
  차단됩니다(`CORBITS_ALLOW_PRIVATE_NETWORK`와 함께, 또는 사이트 목록과 함께 설정하면 시작을 거부합니다). 결과에 영향을 주는 행동은 여전히
  승인이 필요합니다. 가능하면 목록을 쓰세요.
- 샌드박스보다 약한 점: 컨테이너도 송신 프록시도 없으므로, 허용된 사이트에서 사설 주소로의 리디렉션을 네트워크 계층이 막지 못하고,
  다운로드는 실제 다운로드 폴더에 저장되며(다운로드 클릭에는 여전히 승인이 필요), 그 프로필에 로그인된 모든 것에 허용된 사이트에서 접근할
  수 있습니다. 승인, 한도, 검증은 평소처럼 동작합니다.
- 샌드박스도 설정되어 있으면 샌드박스가 기본으로 유지되고, 대시보드의 새 작업 양식에 **내 Chrome에서 실행 (새 탭)**이 표시됩니다(관리자
  전용). 샌드박스가 없으면 모든 작업이 내 Chrome을 씁니다.
- 그 Chrome이 열려 있는 동안에는 이 컴퓨터의 어떤 프로그램이든 제어할 수 있습니다. 쓰지 않을 때는 닫으세요.
- 로컬 전용: Docker나 서버 구성에서는 동작하지 않으며, Chrome이 실행 중이어야 합니다.

## 브라우저 직접 개입하기

CAPTCHA, 2단계 인증, 또는 에이전트가 할 수 없는 단계에서는 작업을 열고 "직접 개입하기"를 눌러서 에이전트의 샌드박스 브라우저를
대시보드에서 직접 조작하세요(그림을 클릭하고, 키보드나 텍스트 상자로 입력합니다. 휴대폰에서도 됩니다). 제어권을 넘겨받기 전에
에이전트가 멈추므로, 나와 에이전트가 동시에 페이지를 조작하는 일은 없습니다. 직접 제어한 시간은 작업의 실행 시간에 포함되지 않습니다.
"에이전트에게 돌려주기"를 누르면 내가 남겨 둔 페이지에서 작업이 재개되고, 에이전트는 페이지가 바뀌었을 수 있다는 것을 알게 됩니다(선택적으로
남긴 메모도 함께 전달됩니다).

- 에이전트가 쓰는 것과 같은 샌드박스 Chromium이며, 내 컴퓨터가 아닙니다. 내 입력도 같은 네트워크 규칙(송신 프록시, 사설 주소 없음)을
  거치며, 스크립트를 실행하거나 페이지를 읽어 들일 방법은 없고 그림만 볼 수 있습니다.
- 입력한 내용은 저장되지 않습니다. 기록에는 제어가 있었다는 사실, 시간, 클릭·텍스트 입력·키 입력·스크롤 횟수, 그리고 내 메모만 남습니다.
- 에이전트가 먼저 나를 부를 수도 있습니다. CAPTCHA, 인증 코드, 로그인 정보가 없는 로그인을 만나면 이유와 함께 `request_help`를 호출합니다.
  작업이 내 제어 아래 일시정지되고(라이브 화면 위에 "도움이 필요합니다" 배지와 이유가 표시됨), 이메일과 메뉴 막대 알림이 오며, 돌려주면
  재개됩니다. 작업당 최대 세 번까지 요청할 수 있고, 그 뒤에는 계속하거나 마무리하고 설명하라는 지시를 받습니다. 도움 요청은 일시정지만 할
  뿐, 무엇도 승인하지 않습니다.
- 실행 중인 작업만 넘겨받을 수 있습니다(대기 중인 승인은 먼저 거부하거나 기다리세요). 라이브 화면은 제어 중에는 초당 약 세 번, 지켜보기만
  할 때는 초당 한 번 갱신됩니다.
- 라이브 화면은 브라우저 세션이 같은 서버 프로세스에 있어야 합니다. 재시작 뒤에는 세션이 사라져서 돌려주기만 할 수 있습니다(그러면
  에이전트가 마지막 페이지를 다시 불러옵니다).

## 이메일 알림

Corbits는 작업이 검증되어 완료되었을 때, 실패했거나 미완으로 끝났을 때, 승인이 필요할 때 작업 소유자에게 이메일을 보냅니다. 메시지는 저장된
작업 상태로 만든 일반 텍스트이며(모델 출력으로 만들지 않음), 한 번에 승인되는 링크는 절대 포함하지 않습니다. `.env`에 SMTP와
`CORBITS_OWNER_EMAILS`를 설정하세요(`.env.example` 참고). Gmail 앱 비밀번호로 되며 비용이 들지 않습니다. 설정하지 않아도 알림은 기록되고,
이메일을 설정하면 그때 발송됩니다. 전달은 최소 한 번(at-least-once)이며 모든 시도가 `notification_attempts`에 저장됩니다.

## 로드맵

아직 만들지 않은 것, 대략 우선순위 순:

1. 스크린샷 폴링보다 부드러운 스트리밍, 그리고 승인 대기 중에도 직접 개입
2. 하나의 공유 Chromium 대신 작업당 컨테이너 하나, 더 강한 격리를 위해
3. Jev 우선·Jev 단독 모드를 더 폭넓게 측정(`pnpm eval` 반복 실행과 더 다양한 케이스)한 뒤에 의존하기
4. `DesktopAdapter` 뒤의 데스크톱(브라우저 외) 실행
5. 자격 증명 키 교체, 에이전트에게 일회용 코드를 안전하게 전달하는 방법, 사이트가 갱신할 때 저장된 로그인을 자동으로 새로 고치기
6. 더 강한 다중 사용자 보안: 내장 HTTPS, 자체 가입과 토큰 재설정, 요청 속도 제한

## 알려진 한계

- 다른 프로세스에서 취소하면 다음 단계 경계에서만 실행이 중단됩니다.
- 브라우저 세션은 워커 프로세스 안에 있습니다. 재시작 뒤에는 마지막 페이지를 다시 불러오지만, 입력하던 폼 상태는 사라지고 모델이 새로
  스냅샷을 찍어야 합니다.
- 검증 증거는 페이지가 제어하는 텍스트입니다.
